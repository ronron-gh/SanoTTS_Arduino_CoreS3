# 小さい辞書を使う日本語文章入力

状態: 2026-09-13、辞書互換性の調査方針に了承を得てホスト検証まで完了。2026-09-13、ユーザー了承により日本語入力exampleを実装し、ビルド・ホスト検証完了。実機確認待ち。

## 目的

k1-dict-44000-2mb.binを使い、漢字かな交じりのUTF-8文章をモデル用トークン列へ変換して、既存のW8A8＋PIE推論・ストリーミング再生につなぐ。固定トークン入力から日本語入力へ移る最初の検証とする。

## 対象範囲

- 作業先は C:\git\SanoTTS_Arduino_CoreS3 のみ。
- examples/05_text_input/ と環境 cores3-text-input を追加する。
- 既存01〜04のmain.cpp、モデル、パーティション、既存環境の動作は維持する。
- 既定環境はcores3-streamingのままとし、日本語入力版は環境名を明示して選択する。
- ユーザーが変更した.gitignoreを保持する。辞書バイナリをGitへ追加しない。

## 調査で分かった前提

- 辞書は977,456バイト、44,000エントリ、K1D1形式v2。
- SHA-256: cd1ed65241600b29ced9fde627b1543d93f5f5c0cd5297a4dba42d3f01d8806a。

## 実装手順

### 1. 辞書形式の互換性を確保する

- matrixc/charr対応の上流jdict.c・jdict.hと関連変更を確認する。出所と対象版を記録し、無関係な推論コア更新は行わない。
- 形式を推測して独自展開を実装しない。対応コードを取得・確認できない場合は、必要ファイルと理由を示して相談する。
- 辞書のマジック、バージョン、必須区画と境界、接続コスト・文字種情報を認識したことを確認する。jdict_openの成功だけを合格にしない。

### 2. 小さい辞書をフラッシュへ埋め込む

- 既存モデルと同様にconst配列として.flash.rodataへ置き、辞書全体をRAMへコピーしない。
- 辞書用ヘッダは.pio/build/<環境>/generated/へ生成し、1つの翻訳単位だけで定義する。16バイト整列を指定する。
- モデル専用blob_to_header.pyのSAAN形式チェックを無効化して流用せず、K1辞書として検証する生成処理を用意する。
- 辞書・生成スクリプトの変更で再生成し、辞書がない・ハッシュ不一致・非対応形式なら明示してビルドを止める。
- 現在の6.25MiBアプリ領域内に収まることをビルドで確認する。専用辞書パーティションと辞書単独の書き込みは追加しない。

### 3. 日本語解析を接続する

- jdict、accent、njd_rules、label_ids、必要なOpen JTalkのCソース、saan_kanjiを組み込む。
- CHARSET_UTF_8、LABEL_IDS_EXTERNAL_SCRATCH等を呼び出し側と解析側でそろえる。
- Open JTalkの動的確保は既存oj_heap_psramを使ってPSRAMへ寄せる。差し替え用ヘッダは対象ソースだけへ適用し、oj_heap_psram.c自身には適用しない。
- 解析は単一タスクで実行する。解析結果のidsはarenaの外へ保持し、解析完了後に同じarenaを推論用に初期化する。
- 最初に「今日は良い天気ですね。」を実際の文章として解析する。小さい辞書によって読みが変わり得るため、固定ids/checksumとの一致を無条件の合否にはしない。
- 解析時間、解析した形態素数・ids数、エラー、メモリを記録する。

### 4. シリアル入力と再生

- 改行で確定するUTF-8行入力を受け付ける。CR/LF/CRLFを扱い、空行、不正UTF-8、過大入力は拒否する。
- 初期上限は入力1,023バイト・モデル入力350 idsとし、上流APIの実際の制約に合わせて確認する。長文を黙って切り捨てず、短く区切るよう案内する。
- 起動時に定型文を解析・再生し、以降は入力文章を解析・再生する。再実行コマンドは/rとし、日本語入力との混同を避ける。
- 解析失敗時は発声せず次の入力を待つ。推論・再生に失敗した際もメモリと音声タスクの状態を安全に処理し、再試行可否を明示する。
- 合成中の入力は無制限に予約しない。受付中のプロンプトが出てから送る方式をREADMEで説明する。

## 注意点・副作用

- 小さい辞書では固有名詞・地名などの読みを誤る可能性がある。入力を受け付けることと正しく読むことを区別して評価する。
- 辞書を含むファームウェアは大きくなるが、パーティションは変更しない。モデル・辞書の出所や配布条件をREADMEで参照する。
- 解析中と推論中でarenaを同時使用しない。Open JTalkの一時ヒープと解析用スタックの余裕を実機ログで確認する。
- ストリーミング開始後に異常を検出した場合、既に出た音は取り消せない。残りを停止してバッファ寿命を守る。
- 既存のユーザー変更やコミットを巻き戻さない。自動コミット・pushは行わない。

- 辞書生成: ハッシュ・区画検査、生成配列と元バイナリの一致、更新追従、欠落・破損時の拒否を確認する。
- ビルド: cores3-text-inputと比較用cores3-streamingを確認する。既存環境へ解析ソース・マクロが混入しないこと、モデル・辞書のフラッシュ配置と整列を検査する。
- 利用可能な範囲で辞書接続コスト・未知語処理とトークン変換を確認する。実機未実行の項目は区別して記録する。
- ユーザーの実機確認: 定型文、ひらがな文、漢字かな交じり文、数字、未知語、空行、上限超過、再実行でログと読みを確認する。
- 長文は入力・ids・内部解析上限のどこで拒否したかを確認し、再度短い文章を処理できることを確認する。
- 実機書き込みはユーザーが行う。追加の依存取得が必要な場合はネットワーク実行前に確認する。
