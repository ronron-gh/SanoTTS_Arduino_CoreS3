# 数字・英字の読み落ち修正

状態: ユーザー了承済み。実装・ビルド・ホスト検証完了。修正後の実機確認待ち。

## 目的・確認できた原因

05で半角数字・英字が無音になる問題を直す。現在は文章を正規化せず辞書へ渡しており、123とOpenAIは読みのない未知語素性になり、NJD処理後の発音が「、」になることをホストで再現した。

全角入力で比較すると、１２３は「百／二／十／三」、ＯｐｅｎＡＩは「オーピーイーエヌエーアイ」へ変わった。後者は英単語の自然な読みではなく文字名読みである。

## 範囲・主な変更ファイル

- examples/05_text_input/japanese_parser.c: 既存Open JTalk text2mecabで入力を正規化してから辞書解析する。
- tests/host/text_e2e.c、必要なホスト検証補助: 半角・全角のids一致に加え、数字・英字の発音が休止だけにならないことを検査する。
- README.md、本ステアリング: 正規化と英字の文字名読み、実機確認手順を記載する。
- 01〜04、推論コア、辞書バイナリ、パーティションは変更しない。

## 実装方針・注意点

- text2mecabの出力容量・戻り値を確認して使う。全角化でUTF-8のバイト長が増えるため、正規化後の鍵バッファ上限も検査し、超過時は切り詰めず拒否する。
- 正規化した文章を一貫して解析へ渡し、読み・ラベル・ids生成へ接続する。既存の作業領域を壊さず、追加バッファ容量を明示する。
- 英単語の読み推定や独自の数値読み規則は追加しない。小数・日付・助数詞の自然さは入力例ごとに確認する。
- 既存テストは解析成功のみでは読み落ちを検出できなかった。読みのある参照とのids比較、数字だけ・英字だけの入力も対象にする。

## 確認・戻し方

- 半角123、全角１２３、OpenAI、ＯｐｅｎＡＩ、既存起動文、正規化で上限を超える入力とその後の復帰をホストで確認。ASan/UBSanを使う。
- cores3-text-inputとcores3-streamingのビルド確認。起動文の固定53 ids一致を維持する。
- 実機で123個あります。とOpenAIで開発します。を再確認してもらう。
- 戻す場合は今回の05の変更だけを戻す。既存の未コミット変更は保持する。自動コミット・実機書き込みはしない。

## 結果

- 辞書解析前にtext2mecabを実行し、正規化後の文章をラベル→ids変換にも渡す。追加バッファはタスクスタック上の1024 B×2。共有arenaには追加しない。
- 342文字のASCII入力が正規化後1026 BとなるケースでTOO_LONGを返し、以降の短文が正常に解析できることを確認。
- 半角/全角123・OpenAIの単独入力と例文のids完全一致を確認。単独入力には実音素が含まれることを検査。
- かな参照とはアクセント・境界記号を除いた音素列を比較。123＝ヒャクニジュウサン、OpenAI＝オーピーイーエヌエーアイが一致。かな表記ではアクセントが違うためids全体の一致は要求しない。
- 7文×3回、起動文の固定53 ids一致、入力境界・エラー後復帰、ASan/UBSan検査に合格。
- cores3-text-input / cores3-streamingビルド成功。新環境flash 2,204,385 B、静的RAM 39,552 B。
- コミット・実機書き込みは行っていない。既存のユーザー変更は保持。
