# Arduino環境でのsanoTTS推論コア検証

状態: レビュー待ち。本文書の承認後に実装する。

## 目的

M5Stack CoreS3の既存Arduino環境でsanoTTS-jpのモデル読み込みと固定トークン列による推論を実行し、AI_StackChan_Exへ移植するためのビルド互換性・実行時メモリ・処理時間を確認する。

## 対象範囲

- 作業先は `C:\git\SanoTTS_Arduino_CoreS3` のみ。AI_StackChan_Exの実装は変更しない。
- 初期検証はモデル読み込み、`demo_ids.h` の固定入力によるPCM生成、シリアルへの結果出力まで。
- 音声再生、かな解析、漢字辞書、顔表示、対話コンソール、通信機能の統合は次段階とする。
- モデルとコピー済みのESP-IDFサンプルは保持し、不要なソースは削除せずビルド対象から除外する。

## 主な変更ファイル

- `platformio.ini`: 対象ソース、必要なマクロ・最適化設定、モデル生成用のビルド処理を登録する。
- `src/main.cpp`: Arduinoのsetup/loopと検証処理を実装する。
- `src/saan_model.c`: 既存のモデル読み込みを再利用し、必要な場合のみ互換性を調整する。
- `lib/saanotts_core/library.json`（新規）: 推論に必要なCソースとビルド条件を明示する。
- `scripts/`（新規）: モデルから16バイト境界に整列した埋め込みヘッダをビルド時に生成する処理を配置する。
- 本ステアリングファイル: 実装・確認結果を追記する。

## 実装方針

1. 現行のespressif32 6.3.2、Arduino、M5Unified 0.2.15、CoreS3設定とパーティションを維持する。環境更新が必要になった場合は方針を再検討する。
2. ESP-IDF用main.cはビルド対象から外し、Arduinoの起動処理との競合を避ける。CMakeによるソース選択・定義のうち検証に必要なものをPlatformIOへ移す。
3. 推論コアはsaanotts.c、saanotts_stream.c、saanotts_int8.c、fft.cを基本とし、実際の参照関係に合わせて最小構成を確定する。
4. student_i8.binから生成するヘッダはビルド出力内に置き、モデル更新時に再生成する。モデルのサイズ・形式・アラインメントを検査し、コア側の読み込みエラーを表示する。
5. 固定入力を一度推論し、PCMをチャンク単位で処理する。全音声を保存せず、サンプル数、非有限値の有無、振幅の統計、再現性確認用チェックサムを集計する。
6. 初期化・推論の成否、処理時間、生成音声の長さ、実時間比、作業領域の使用量と空きヒープをシリアルへ表示する。
7. まず移植可能なC経路で成立を確認する。ESP32-S3のPIE最適化は別設定として、ツールチェーン互換性を確認できる場合に比較する。異なる演算経路間のチェックサム一致は前提にしない。

## 設計上の注意点・副作用

- C/C++のリンケージ、Cコンパイル条件、モデルの16バイト整列を維持する。
- 推論用arenaは実装の必要量と内部RAMの連続空き領域を確認し、確保失敗・推論失敗を明示して停止する。PSRAM使用時は配置をログに残し、内部RAMの場合と速度を混同しない。
- 長時間推論によるWatchdogやタスクスタック不足に注意し、必要なら専用タスクやチャンク間の待機を使う。Watchdogの一律無効化は避ける。
- 既存サンプルのESP-IDF 5系診断API、辞書、UI、他ボード用音声処理を初期検証へ持ち込まない。
- ユーザーが追加したモデルやソース、Hello Worldのコメント済みコードを無関係に書き換えない。main.cppを置き換える場合は元の内容を退避する。
- 新たなモデル・辞書・ライブラリのダウンロードは本作業に含めない。

## 確認方法

- 静的確認: ソース選択、モデルヘッダ生成と更新追従、整列、マクロの整合性、既存ファイルの保持を確認する。
- ビルド: インストール済みのツールと依存を使い `m5stack-cores3` を確認する。依存取得が必要な場合はネットワーク実行前にユーザーへ確認する。
- 実機: ユーザーによる書き込み・実行後のシリアルログで、モデル読み込み成功、推論完了、PCMサンプル数が正であること、非有限値がないこと、再起動やメモリ不足がないことを確認する。
- 同一構成でのチェックサム再現性を確認する。参照値と比較する場合は入力・モデル・演算経路・PCM変換方法が一致する条件に限定する。
- 実機ログが得られるまでは「ビルド確認済み」と「推論動作確認済み」を区別する。音質・音声再生の正常性は今回の合格条件に含めない。
- 実機への書き込みは本作業では実行しない。

## 戻し方

実装前の変更対象ファイルを退避し、本作業で追加したビルド設定・スクリプト・検証コードのみを戻す。ユーザー追加のlib/modelとESP-IDFサンプルは保持する。パーティションや実機の保存データは変更しない。
